# Contributing

Thank you for helping improve AstroBridge's public website and documentation.

1. Open an issue describing the proposed change, unless it is a security issue.
2. Keep claims measurable and link to primary evidence.
3. Label internal tests, automated external scans, and independent reviews
   separately.
4. Run `npm ci` and `npm test` before opening a pull request.
5. Never commit credentials, personal data, local databases, signing files, or
   generated dependency folders.

Security reports must follow [SECURITY.md](SECURITY.md) instead of public issue
tracking.
